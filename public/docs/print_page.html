    Common Knowledge Scout Documentation¶

    Common Knowledge Scout turns the files in your own storage — audio, video, PDFs, images and web pages — into structured Markdown, and makes the result available as a gallery, a website and a chat that answers with sources.

    For an overview of what the application does, see the README on GitHub.

    About this site¶

    This site contains the maintained pages only. Plans, architecture decisions, contracts and working notes of the development are kept in the docs/ folder of the repository; most of them are written in German.

    Architecture overview¶

    This page describes how Common Knowledge Scout is built: the services it needs, how the code is organised, and the decisions that shape it. It is the entry point for developers; the detailed documents it links to are in the repository and mostly written in German.

    The system and its neighbours¶

  subgraph Clients
    B[Browser]
    A[AI agent<br/>MCP client]

  end
  subgraph KS[Common Knowledge Scout · Next.js]

  API --> DB[(MongoDB<br/>data and vector search)]
  API --> BLOB[(Azure Blob<br/>published media)]
  UI --> CL[Clerk<br/>sign-in]
    Component Role
    Common Knowledge Scout A Next.js application (App Router). It serves the interface, the API, the MCP server and runs the job worker in the same process.
    Secretary Service A separate Python service. It performs transcription, text recognition, PDF and office extraction, and every call to a language model. The application holds no model provider key.
    User storage The folder a library points at. Source files stay here and are never moved.
    MongoDB Libraries, documents, shadow twins, jobs, question log, and the vector index used for retrieval.
    Azure Blob Storage Optional. Holds images and media of published documents so that they can be served without access to the user's storage.
    Clerk Sign-in and user management.

    How the code is organised¶

    The repository is a pnpm monorepo.

    Location Content
    src/app/ Pages and API routes
    src/components/, src/lib/ Interface components and server logic of the application
    packages/ Shared code and feature modules, imported as @ks/*
    electron/ The desktop shell
    extensions/knowledgescout/ The Claude Desktop extension that connects to the MCP server
    template-samples/ Example templates
    docs/ Contracts, architecture decisions, plans and this documentation

    The packages are layered. A package may import from the layers below it, not from those above.

    Layer Packages Content
    Shared @ks/contracts, @ks/util, @ks/ui, @ks/i18n, @ks/viewers, @ks/api-client Types, interface primitives, translations, Markdown rendering, a typed API client
    Shell @ks/shell Providers, navigation, and the mapping from a host name to a site
    Modules @ks/module-explorer, @ks/module-story The gallery and story mode, each with its components and API namespace
    Embedding @ks/embed Gallery and story mode as one component for other React applications

    Moving code from src/ into packages is ongoing work. The target layout and the order of the moves are described in the module map.

    Storage abstraction¶

    All access to files goes through one interface, StorageProvider (src/lib/storage/types.ts), with an implementation for the local file system, OneDrive and Nextcloud. A provider is obtained from StorageFactory, on the server through getServerProvider(). Features do not ask which backend a library uses; only the settings forms do, to show the right fields.

    Credentials for OneDrive and Nextcloud belong to a user account as a storage connection. They are encrypted with AES-256-GCM before they are stored.

    Rule: storage abstraction.

    From file to answer¶

    flowchart LR
  S[Source file] -->|1 Extract| T[Transcript]
  T -->|2 Transform<br/>with a template| D[Document<br/>Markdown + front matter]
  D -->|3 Ingest| V[Passages with embeddings]
  V --> G[Gallery]
  V --> Q[Story mode]

    Jobs. Each processing request becomes a job in MongoDB. A worker that starts with the server claims jobs, calls the Secretary Service and receives the result through a callback. Several instances can share one database when each has its own pool ID. All requests enter through one endpoint, POST /api/pipeline/process, and choose which of the three phases to run and whether to overwrite existing results.

    Shadow twin. The transcript and the transformed document of a source are its shadow twin. Twins are stored in MongoDB, one collection per library. A library can also keep a mirror as Markdown files in a folder named _<source file name> next to the source, so that agents and other tools can read them. The database is the truth for generated twins; export and import between the two are explicit actions, not a permanent synchronisation.

    Front matter. The metadata of a document is flat: snake_case keys on one level, compatible with Obsidian. One serialiser writes it.

    Index. Ingestion writes three kinds of records into the library's vector collection: one metadata record per document, the passages with their embeddings, and chapter summaries with their embeddings. The gallery reads the metadata records. Filter fields are copied onto the passages so that a search can be filtered directly. The embedding model and its dimension are set per library.

    Answering. A question is embedded and matched against the passages with MongoDB vector search, limited by the active filters and, for visitors, to published documents. The best passages go to the language model with the question, the reader's perspective and the library's answer rules. Answers are stored in a question log that also serves as cache.

    Rules: pipeline, shadow twin, ingestion, chat.

    One deployment, many sites¶

    A site is a configuration, not a separate build. The application resolves the host name of a request to a library and renders that library's website at /, without the navigation of the application. Embedding in another website uses @ks/embed, which talks to the same API and serves public content only.

    MCP server¶

    The MCP server is a Streamable HTTP endpoint at /api/mcp/mcp. A request is authenticated with a personal account key and runs as that user. Each tool is a thin layer over the function the interface calls, so behaviour and validation are the same on both paths. Tools that change something require a reason and write it to an action log.

    Principles¶

    Principle Meaning
    No silent fallbacks An invalid or missing value causes an error or an explicit log entry. It is never replaced by a default without notice.
    The interface does not know the storage backend Features use the provider interface.
    Capture and publish are separate Submitted content goes to an inbox first. Publishing is a separate, permission-checked step.
    Machine work counts as accepted People mark what is wrong instead of confirming what is right.
    Public repository Documentation describes the application, not a particular library, organisation or person.

    Architecture decisions¶

    ADR Decision Status
    0001 Event jobs and external jobs are separate domains Active
    0002 Gallery stars come from MongoDB, not from Clerk Active
    0004 Capture writes to an inbox; publishing is a separate job Active
    0006 Curation marks errors instead of confirming results Active

    Create a library and connect storage¶

    What you achieve¶

    A library is a folder in your own storage together with everything Common Knowledge Scout knows about it: the documents made from your files, the gallery, the website and the settings. After this guide you have a library that points at your files and is ready for processing.

    Language of the interface

    Most of the interface is in German. This guide gives the label as it appears on screen, followed by an English translation.

    Before you start¶

    • You are signed in.
    • You know where the files are: on the server's file system, in OneDrive or in Nextcloud.
    • For OneDrive you need the tenant ID, client ID and client secret of an app registration. For Nextcloud you need the WebDAV address, your user name and an app password.

    Step 1: Add a storage connection¶

    Skip this step if the files are on the server's file system.

    Access to OneDrive and Nextcloud belongs to your account, not to a single library. You sign in once and use the connection for as many libraries as you like. The credentials are stored encrypted.

    1. Open Settings → Speicher-Verbindungen (storage connections).
    2. Click Neue Verbindung (new connection).
    3. Enter a Bezeichnung (name) and choose the Typ:
      • Nextcloud (WebDAV): WebDAV address, user name, app password.
      • OneDrive (Microsoft 365): tenant ID, client ID, client secret.
    4. Click Anlegen (create).
    5. For OneDrive, click Anmelden (sign in) on the new card and complete the Microsoft sign-in.
    6. Click Testen (test) to confirm that the connection works.

    A connection cannot be deleted while a library uses it.

    Step 2: Create the library¶

    1. On the start page, click Neue Bibliothek (new library). The same entry is in the library switcher at the top of the page.
    2. Go through the steps of the dialog. Three things are required; everything else is a recommendation you can change later.
    Step What you decide Required
    Grundlagen (basics) The name and what the library will contain, for example books and documents, or events and sessions. You can copy the configuration of an existing library of the same kind. Name, content type
    Quelle (source) Where the files are: Nextcloud, OneDrive or a local directory on the server. For cloud storage you choose a connection and a folder on it; for local storage you enter an absolute path. Yes
    Verarbeitung (processing) How files are transformed by default No
    Finden (finding) How visitors explore the gallery No
    Story How answers to questions are given No
    Erfassen (capture) Forms for adding new content. Shown only for content types that have them. No
    Zusammenfassung (summary) A review of your choices –
    1. Click Bibliothek anlegen (create library).

    The library appears in the library switcher. Open Archive in the top navigation to see its files.

    Step 3: Invite people¶

    Only the owner of a library can do this.

    1. Open Settings → Personen (people).
    2. Click Person einladen (invite a person).
    3. Enter the e-mail address, choose a role and, if you like, add a personal message.
    Role What the person can do
    Leser (reader) Read the library
    Mitwirkender (contributor) Submit content, but not publish it
    Co-Creator Work in the archive, gallery, story mode and templates, without access to the settings
    Moderator Handle access requests and send invitations

    Where the settings are¶

    Section What it controls
    Library Name and basic settings
    Archive Storage source, content type and processing defaults
    Explore How visitors browse the gallery
    Story How answers sound and which rules they follow
    Fragen & Antworten (questions and answers) Stored answers
    Erweitert (advanced) Search and models, storage of twins, extraction, maintenance
    Personen (people) Members and roles
    Öffentlicher Auftritt (public presence) Publishing the library
    Zugriffsanfragen (access requests) Requests from people who want access
    Mein Zugang, Speicher-Verbindungen Your account: agent access and storage connections

    To change the storage of an existing library, open Settings → Archive → Quelle (source).

    Transform files into documents¶

    What you achieve¶

    A recording, a PDF or an image in your storage becomes a structured document with a title, a summary and metadata, and that document becomes searchable. The original file is not changed.

    Language of the interface

    Most of the interface is in German. This guide gives the label as it appears on screen, followed by an English translation.

    The three steps of processing¶

    Step Label in the interface What it produces
    1. Extract Transkript erstellen (create transcript) The plain text of the source: a transcript for audio and video, recognised text for PDFs, images and office files
    2. Transform Artefakte generieren (generate artefacts) A document shaped by a template: front matter with metadata, a structured body and, if you want, a cover image
    3. Publish Story publizieren (publish story) The document is split into passages and indexed, so that it appears in the gallery and can be used to answer questions

    Each step can be switched on or off, and each can be repeated on its own. The result of steps 1 and 2 is called the shadow twin of the source. It is stored in the database; a library can be set to write a copy as Markdown files into your storage as well.

    Supported sources: PDF, audio (mp3, m4a, wav, ogg, opus, flac), video (mp4, mov, avi, webm, mkv, mpeg), images, Word, Excel and PowerPoint files, and Markdown. Markdown files skip step 1.

    Before you start¶

    • A library with connected storage (see Create a library).
    • The Secretary Service is running. It does the transcription and text recognition.

    Process one file¶

    1. Open Archive and select the file.
    2. In the preview, open the sheet Aufbereiten & Publizieren (prepare and publish).
    3. Switch on the steps you want. A badge shows whether a result exists already and whether it will be overwritten.
    4. Set the options:
      • Transcript: source and target language for audio and video. For audio you can add context such as the topic and special terms.
      • Artefacts: the Vorlage (template), the language, the model, whether to generate a cover image, and optional notes for corrections.
    5. Click Jetzt starten (start now).

    A progress bar in the preview shows the run. When it is finished, the tabs Original, Transkript, Transformation, Story and Uebersicht (overview) show the source and each result. To redo a step, use Neu generieren (regenerate) or Erneut publizieren (publish again) in the corresponding tab.

    Process a whole folder¶

    1. In Archive, open the folder.
    2. Click Verzeichnis verarbeiten (process directory) in the header. To process only some files, tick them in the list first.
    3. Choose the steps. Erzwingen (force) repeats a step for files that have a result already.
    4. Optionally give the run a name and limit it with a file name pattern; * is the wildcard.
    5. Click Jobs starten (start jobs).

    The folder and all its subfolders are scanned. Template, language and extraction method come from the library's defaults. Folders whose name starts with _, and folders named test or tests, are skipped; the dialog shows how many.

    Follow progress and errors¶

    Open the job monitor from the header of the application. It lists the running and finished jobs, can be filtered by run, shows the error of a failed job under Details anzeigen (show details), and restarts failed jobs.

    Templates¶

    A template decides what the document looks like. It consists of the metadata fields to fill, instructions for the language model and the layout of the body. Templates are managed under Templates in the top navigation, where you can also test one against a file.

    The folder template-samples/ in the repository contains examples that can be imported.

    Web pages and video playlists¶

    Importing a web article together with its embedded audio or video, or a whole video playlist, is available through the agent tools, not through the interface. See Operate a library with an AI agent.

    Publish a gallery and a website¶

    What you achieve¶

    People can browse the documents of your library without signing in, at an address of its own. If you want more than a gallery, the library also gets a website whose pages you write as Markdown files in your storage.

    Language of the interface

    Most of the interface is in German. This guide gives the label as it appears on screen, followed by an English translation.

    Before you start¶

    • You own the library.
    • At least one file has gone through all three processing steps (see Transform files into documents).

    Open the library to the public¶

    1. Open Settings → Öffentlicher Auftritt (public presence).
    2. Switch on Library veröffentlichen (publish library).
    3. Enter the Web-Adresse (Slug): lowercase letters, digits and hyphens. It must be unique on the instance.
    4. Fill in Öffentlicher Name (public name) and Öffentliche Beschreibung (public description).
    5. Click Veröffentlichung speichern (save).

    The library is now available at /explore/<slug>. The form shows the link.

    Further options on the same page:

    Option Effect
    Zugriff nur für freigegebene Benutzer (access for approved users only) Visitors must sign in and be approved
    Auf der Startseite anzeigen (show on the start page) The library appears as a card on the start page of the instance, with the icon and Hintergrundbild (background image) you choose
    Sterne-Zahl öffentlich zeigen (show star counts publicly) Visitors see how many stars a document has. The names of the people who gave them are never shown.
    Galerie-Texte (gallery texts) Headline, subtitle, introduction, an explanation of the filters, and the name of the gallery in the menu
    Bezeichnung eines Eintrags (name of an entry) What a document is called in this library, singular and plural, for example "measure" and "measures"

    Which documents are visible¶

    A document appears in the gallery once the step Story publizieren has run for it. Each document is either published or a draft. Drafts are hidden from visitors and are not used to answer their questions.

    In the gallery, as owner, switch to the table view to see the status of each document and to use Publish, Unpublish and Publish all.

    What visitors see¶

    The gallery has two views, and every visitor can switch between them:

    View For What it shows
    Simple People who come to read Compact cards, filters in a drawer, a short introduction, and a switch between the documents in focus and all documents
    Expert People who work with the material All tools: table and graph views, full filters, story mode

    In focus is the ranking by stars that members of the library have given. Under Settings → Explore you choose which view opens first and whether the gallery starts in focus or with all entries.

    Useful addresses:

    Address Opens
    /explore/<slug> The website if there is one, otherwise the gallery
    /explore/<slug>?view=gallery The gallery
    /explore/<slug>?mode=story Story mode
    /explore/<slug>?site=<page> A page of the website

    Add a website¶

    A website is a set of Markdown files in the library. Each file is one page.

    1. Create the pages as Markdown files, by convention in the folder Webseite/Seiten/.

    2. Give each page front matter. The front matter is flat: one level of snake_case keys.

      ---
detailViewType: website
title: About
slug: about
menu_order: 2
hero_layout: band
hero_title: About this project
---

    3. Structure the body with sections:

      <!-- section layout=image-left -->
## Why we do this
Text of the section.
<!-- /section -->

    4. Process each page like any other file, so that it is published.

    5. In Settings → Öffentlicher Auftritt, switch on Website am Slug anzeigen (show website at the slug) and set the Website-Logo.
    Front matter Purpose
    title, slug, menu_order, menu_area Name in the menu, address, position, and whether the page is in the main menu, the footer or hidden
    hero_layout, hero_title, hero_subtitle, hero_image, cta_label, cta_url The opening area of the page and its button
    banner_tag, banner_title, banner_limit, banner_sort A row of documents from the gallery on the page
    Section layout Content
    text-only, image-left, image-right, full-image, video Text and media
    banner Documents from the gallery
    story A question box that answers from the library, with example questions. One per page.
    contact-form A contact form

    Inside a section, the blocks <!-- cards -->, <!-- stats -->, <!-- chips --> and <!-- box --> add tiles, figures, tags and highlighted text.

    The complete syntax is in the website contract (German). An agent can create, check and publish the pages for you; see Operate a library with an AI agent.

    Use your own domain¶

    The operator of the instance maps a domain to your library with the setting PUBLIC_DOMAIN_LIBRARY_MAP, for example {"example.org":"my-library"}. The domain then shows the library's website at /, without the navigation of the application. See Configuration.

    Embed the gallery in another website¶

    The package @ks/embed provides the gallery and story mode as a React component:

    import '@ks/embed/styles.css'
import { KnowledgeScoutExplorer } from '@ks/embed'

<KnowledgeScoutExplorer
  baseUrl="https://your-instance.example"
  library="my-library"
  view="gallery"
  locale="en"
/>

    The embedded component shows only what is visible without signing in. It has no sign-in of its own, and libraries that require one are not shown. The package is built from this repository; it is not published to a public registry.

    Ask questions in story mode¶

    What you achieve¶

    You ask a question in your own words and get an answer written from the documents of the library, with a numbered reference to every document it used. You can check each statement against its source.

    Before you start¶

    • The library has published documents (see Transform files into documents).
    • For visitors without an account, the library is public (see Publish a gallery and a website).

    Open story mode¶

    • Choose Story Mode in the navigation of the library, or
    • click View in Story Mode in the gallery or in a document, or
    • open /explore/<slug>?mode=story.

    The screen has three parts:

    Part Content
    Chronicle (left) The topics of the library, your earlier questions, and New session
    Middle A topic overview generated from the library's documents, the questions suggested for each topic, and the conversation
    Evidence (right) The documents an answer cites

    Set your perspective¶

    The first time you open story mode, a dialog asks How should answers be formulated for you? You can reopen it at any time with Adjust perspective.

    Setting Choices
    Language The language of the answers
    Thematic Interests Up to five, for example technology, society and culture, ecology and sustainability, education and learning
    Access Perspective Up to five, for example insight-oriented, practice-oriented, future-oriented
    Language Style One of scientific, generally understandable, youth-oriented, professional, child-friendly, simple language and others
    Advanced Settings The language model

    The perspective changes how an answer is worded and what it emphasises. It does not change which documents are available.

    Ask a question¶

    1. Pick one of the suggested questions of a topic, or open the question box with the round button at the bottom right and type your own.
    2. Choose the Answer length: Short, Medium, Detailed or Unlimited.
    3. Send the question. While the answer is written, the steps are shown in plain words.

    Each answer comes with:

    • Citation numbers in the text. One number stands for one document. Click a number to jump to that document in the evidence column.
    • Evidence cards that show how many passages of the document were used and, where known, the page.
    • Other documents found: documents that matched the question but were not cited.
    • Follow-up questions that you can ask with one click.

    Next to your question you find Ask again and Delete question.

    Limit a question with filters¶

    Filters you set in the gallery stay active in story mode. A question then searches only the documents that match them. The active filters are shown as chips next to the document counts.

    How an answer is found¶

    The question is compared by meaning, not by keywords, with the passages of all documents. The passages that fit best are given to the language model together with your question, your perspective and the rules of the library. The model writes the answer from these passages and marks which document each statement comes from.

    Answers are stored. When the same question is asked again under the same conditions, the stored answer is shown.

    For library owners: shape the answers¶

    Where What you set
    Settings → Story → Antwortregeln (answer rules) Instructions every answer must follow, written as text. They can refer to the values of a metadata field, for example the status of a measure, so that something rejected is not described as decided.
    Settings → Story → Benannte Regelsätze (named rule sets) Alternative sets of rules. A story section on the website selects one with rules=.
    Settings → Erweitert → Suche & KI (search and models) The meaning of each value of a metadata field, and the models used
    Settings → Öffentlicher Auftritt What a document is called, for example "5 talks cited"

    After an answer is written, it is checked against the metadata of the cited documents. The result is added as a note below the answer; the text of the answer is not changed.

    For library owners: review stored answers¶

    Settings → Fragen & Antworten (questions and answers) lists every stored question with its date, language, model, number of sources and state:

    State Meaning
    aktuell (current) The answer matches the present rules and documents
    veraltet (outdated) The rules, the metadata values or the number of documents have changed since the answer was written
    verworfen (discarded) You have discarded the answer; the question will be answered afresh next time

    Verwerfen discards one answer, Alle Antworten verwerfen all of them. Nothing is deleted; discarded answers stay in the log.

    Who can ask¶

    • In a public library, anyone can ask without an account.
    • Drafts are used only for owners and moderators. Visitors and signed-in people who are not members get answers from published documents only.

    Operate a library with an AI agent¶

    What you achieve¶

    An AI agent such as Claude works on your library for you: it checks what has been processed, starts transformations, publishes pages, changes settings and measures the quality of answers. It does this through an MCP server that is part of Common Knowledge Scout.

    Every tool calls the same function as the user interface. There is no second set of rules for agents.

    Before you start¶

    • You are signed in and own at least one library.
    • The operator of your instance has enabled the MCP server (see Configuration). If it is not enabled, the server answers with HTTP 503.
    • You use Claude Desktop. This is the client the application ships an extension for.

    Connect Claude Desktop¶

    The settings page for this is in German.

    1. Open Settings → Mein Zugang and find the card Claude-Zugang (MCP).
    2. Click Erweiterung herunterladen (.mcpb). The downloaded file contains the address of your instance and a personal key.
    3. In Claude Desktop, open Settings → Extensions, choose to install an extension and select the file.
    4. Ask Claude to list your libraries. If it answers with their names, the connection works.

    Things to know about the key:

    • It is never displayed. It exists only inside the downloaded file.
    • Each download creates a new key. An extension installed from an older download stops working.
    • It acts as you. The key has the full rights of your account in all your libraries and cannot be limited to reading. Give it only to an agent you would trust with write access.
    • You can withdraw it with Schlüssel widerrufen on the same card.

    What the agent can do¶

    The server offers 80 tools (tool set 2.70.0). Tool names are German.

    Area Examples What they do
    Libraries and storage bibliotheken_auflisten, bibliothek_anlegen, speicher_verbindung_testen List and create libraries, test and assign storage connections
    Files ordner_listen, datei_lesen, datei_patchen, verschieben Read, write, move and delete files and folders in the library's storage
    Coverage and twins abdeckung_scannen, twins_pruefen, twins_synchronisieren Find sources that are not processed yet, check and repair shadow twins
    Transformation and jobs quelle_erschliessen, transformation_starten, batch_bilanz, batch_neustart Transcribe or extract a source, apply a template, summarise a batch run, restart failed jobs
    Web capture webseite_erschliessen, playlist_erschliessen Import a web page or a video playlist as sources
    Documents and index dokumente_auflisten, bestand_pruefen, index_aktualisieren List gallery entries, audit the index, rebuild it from existing transformations
    Publishing dokument_publizieren, seite_pruefen, veroeffentlichung_setzen Publish and withdraw documents, check the website, change publishing settings
    Configuration konfiguration_lesen, konfiguration_setzen Read and change the library's chat and gallery configuration, with the same validation as the settings form
    Questions frage_stellen, golden_set_fahren, fragen_log, antworten_verwerfen Ask story mode a question, run a fixed set of test questions, review and discard stored answers
    Log protokoll_lesen, bruecke_info Read why actions ran; report the tool set version and what changed

    Rules the tools follow¶

    • Writing needs a reason. Every tool that changes something requires a short reason and records it in an action log, which protokoll_lesen reads back.
    • Batches are limited. A batch takes up to 30 sources, a folder batch up to 200. An error is reported for the affected row; the rest of the batch continues.
    • Long work runs as a job. A tool call has to finish within about 60 seconds. Anything longer is started as a job, and the agent asks for its status.
    • Working folders are skipped. Batches never enter folders whose name starts with _, or test/.
    • Nothing is assumed silently. When a check cannot run or a value is invalid, the tool says so and does not fall back to a default.

    Ready-made procedures¶

    The repository contains instructions ("skills") that guide an agent through a complete task:

    Skill Task
    veranstaltung-aufbereiten Take the recordings and slides of an event to published pages, with a stop for a person to review the transcripts
    webseite-erschliessen Turn a web article or a video playlist into gallery documents
    website-publishing Create, check and publish the pages of a library's website
    archiv-aufraeumen Bring a folder in order: check coverage, process what is missing, name files consistently

    They are in .claude/skills/ and are written in German.

    If something does not work¶

    • Claude sees fewer or different tools than expected. Claude Desktop keeps a copy of the tool list. Switch the extension off and on under Settings → Extensions; bruecke_info shows which tools the server expects.
    • Access is refused (401). The key was replaced by a newer download or withdrawn. Download the extension again and reinstall it.
    • Service unavailable (503). The MCP server is not configured on this instance.

    Operations

    Configuration¶

    Common Knowledge Scout is configured through environment variables. Use .env.local for development and .env or your container environment for production. .env.example and docker-compose.example.yml are the starting points.

    Secrets belong in the environment only. They are never sent to the browser.

    Required services¶

    Service Purpose
    MongoDB with vector search Libraries, documents, shadow twins, jobs and the retrieval index
    Secretary Service Transcription, OCR, PDF extraction and all language-model calls
    Clerk Sign-in and user management
    Azure Blob Storage (optional) Published images and media

    Application¶

    Variable Required Description
    NEXT_PUBLIC_APP_URL Yes Public URL of the application, for example http://localhost:3000
    PORT No Port of the Next.js server (default 3000)
    PUBLIC_DOMAIN_LIBRARY_MAP No JSON object that maps a domain to a library slug. A mapped domain shows that library's website at /. Invalid JSON is logged and ignored.
    NEXT_PUBLIC_DEBUG_DETAIL No true shows developer details at the end of the session detail view

    Internal calls¶

    Variable Required Description
    INTERNAL_TEST_TOKEN Production Shared secret for server-to-server calls, sent as X-Internal-Token. Without it, job callbacks fail in production.
    INTERNAL_SELF_BASE_URL No Base URL for calls of the application to itself, for example http://127.0.0.1:3000

    Secretary Service¶

    Variable Required Description
    SECRETARY_SERVICE_URL Yes URL of the Secretary Service API. A library can override it under Settings → Transformation.
    SECRETARY_SERVICE_API_KEY Yes API key for the Secretary Service
    EXTERNAL_REQUEST_TIMEOUT_MS No Timeout for requests to the service (default 600000)
    EXTERNAL_TEMPLATE_TIMEOUT_MS No Timeout for template processing (default: the value above)

    MongoDB¶

    Variable Required Description
    MONGODB_URI Yes Connection string
    MONGODB_DATABASE_NAME Yes Database name
    MONGODB_COLLECTION_NAME No Collection that holds the libraries (default libraries)

    Chat and story mode¶

    All language-model calls go through the Secretary Service; no model provider key is configured here.

    Variable Required Description
    QUESTION_ANALYZER_MODEL Yes Model used to analyse a question. There is no default.
    QUESTION_ANALYZER_TEMPERATURE Yes Temperature for question analysis. There is no default.
    LLM_CHAT_TIMEOUT_MS No Timeout for a chat request (default 240000)

    Storage connections¶

    Storage access (Nextcloud app password, OneDrive client secret and tokens) belongs to a user account and is stored encrypted in MongoDB.

    Variable Required Description
    CREDENTIALS_ENCRYPTION_KEY Yes 32-byte key, Base64 or hex, for AES-256-GCM encryption of stored credentials. Without it, creating or reading a storage connection fails. Generate one with openssl rand -base64 32.
    MS_REDIRECT_URI OneDrive Redirect URI of the OneDrive sign-in
    AZURE_STORAGE_CONNECTION_STRING No Azure Blob Storage for published images and media. A library can set its own values under Settings → Story.
    AZURE_STORAGE_CONTAINER_NAME No Container name for the above

    MCP server¶

    The MCP server is available at /api/mcp/mcp (Streamable HTTP). Without configuration it is closed and answers with HTTP 503.

    Variable Required Description
    MCP_API_KEY For MCP Secret that signs the personal account keys users create in their account settings. An account key acts with the full rights of its owner.
    MCP_USER_EMAIL No User for the legacy mode in which MCP_API_KEY itself is used as the key

    Job worker¶

    Variable Required Description
    JOBS_WORKER_AUTOSTART No Start the worker with the application (default true)
    JOBS_WORKER_INTERVAL_MS No Polling interval (default 2000)
    JOBS_WORKER_CONCURRENCY No Number of jobs that run at the same time (default 3)
    JOBS_WORKER_POOL_ID No Set a different ID per instance when several instances share one MongoDB, so each worker claims only its own jobs

    Capture¶

    Variable Required Description
    SUBMISSION_MAX_FILE_BYTES No Largest file accepted by the capture inbox (default 100 MiB). Larger uploads are rejected with HTTP 413.
    SUBMISSION_MAX_TOTAL_BYTES No Largest total size of one submission (default 250 MiB)
